## 1. Резюме

| Параметр | Значение |
| :--- | :--- |
| **Жанр** | Сатирический 3D-симулятор преподавателя, стелс-наблюдение |
| **Камера** | От первого лица (FPS) |
| **Игрок** | Один преподаватель в компьютерном классе |
| **NPC** | 15 учащихся, у каждого характер и свой способ списывания |
| **Локация** | Одна аудитория (10 × 12 м), 15 рабочих мест + стол преподавателя |
| **Сессия** | Подготовка 90 с + пара 10 мин + итоги |
| **Цель** | Ни один учащийся не сдал списанную работу |
| **Провал** | Хотя бы один учащийся сдал списанную работу |
| **Платформа** | Windows 10/11 x64, офлайн, клавиатура + мышь |
| **Язык** | Русский |
| **Рейтинг** | 12+, дисклеймер при первом запуске |

**Одним предложением.** Игрок сидит за столом преподавателя, смотрит трансляцию 15 мониторов, ходит по классу, ловит взгляды, собирает доказательства, раздаёт варианты, отвечает на вопросы и сдаёт телефоны в коробку — и всё это ради одного: чтобы никто не списал.

## 2. Столпы

1. **«Смотри, а не кликай».** Главный ресурс — внимание. Нельзя уследить за всеми сразу.
2. **«Место решает».** За столом видно все экраны, но не видно телефонов. В классе видно руки, но не видно чужих мониторов. Игрок постоянно выбирает, чем пожертвовать.
3. **«У каждого читера есть причина».** Кто-то не успевает, кто-то боится, кто-то наглый, кто-то просто не понимает задание.
4. **«Доказательство важнее подозрения».** Замечание можно дать по подозрению, но серьёзная санкция требует улики. Ошибка стоит доверия класса.
5. **«Сатира, а не инструкция».** Все персонажи и колледж вымышлены, способы списывания показаны условно.

## 3. Канонические определения

Эти определения используются в коде, тестах и текстах. Любое расхождение — баг.

| Термин | Определение |
| :--- | :--- |
| **Сдача** | Ученик завершил лабораторную: `lab_progress >= lab_target` и прошла анимация сдачи 2,5 с. |
| **Списанная работа** | Работа, в которой `copied > 0` на момент завершения сдачи. Любая доля. |
| **Успешное списывание** | Сдача списанной работы. Только это событие приводит к поражению. |
| **Пойман** | К ученику применена санкция, для которой выполнены её условия (см. §12). |
| **Спрятался** | Ученик перешёл в `HIDE` и скрыл нарушение (Alt+Tab / телефон в карман). Прогресс не сбрасывается. |
| **Подозрение** | Наблюдаемый признак без доказательства. Достаточно для замечания, недостаточно для конфискации. |
| **Доказательство (улика)** | Скриншот экрана ученика с таймкодом **или** прямое наблюдение нарушения ≥ 1,0 с с расстояния ≤ 3 м. |
| **Вариант** | Номер задания 1–15. У каждого ученика ровно один **основной** вариант. |
| **Дополнительный вариант** | Второе (и далее) задание, назначенное пойманному ученику. Каждое добавляет +100% к цели. |
| **Отчёт** | Файл с описанием выполненной работы. Без него сдача — `отч`, а не `зач`. |
| **Платная отработка** | Реальный статус `чек` из журнала. В игре не используется. |
| **Дубликат** | Одинаковый вариант у двух учеников. Ускоряет списывание у соседей. |
| **Ложная санкция** | Санкция применена к ученику, который в этот момент не нарушал. |
| **Доверие класса** | Глобальный показатель 0–100. Влияет на поведение, но **не является условием победы или поражения**. |

**Иерархия правил:** 1) требования [Т] → 2) этот документ → 3) старые файлы. Если два правила противоречат, побеждает верхнее.

### 4.5 Посадка и ориентация [Т]

| Места | Куда смотрит ученик | Куда смотрит экран |
| :--- | :--- | :--- |
| T1–T3 | В верхнюю стену | Вниз, в класс |
| L1–L4 | В левую стену | Вправо, в класс |
| R1–R4 | В правую стену | Влево, в класс |
| C1, C2 | Внутрь острова, вправо | Влево, в левый проход |
| C3, C4 | Внутрь острова, влево | Вправо, в правый проход |
| Преподаватель | Вверх, в класс | Экран ПК — к преподавателю, от учеников |

- Все ученики сидят спиной к проходу: преподаватель подходит сзади и видит экран через плечо.
- Руки ученика находятся по дальнюю сторону стола (у стены или в центре острова), поэтому сзади видны хуже, чем экран. Для проверки рук нужен заход сбоку или наклон `C`.
- Центральный остров — зона, где проще всего спрятать телефон: руки уходят внутрь острова, в узкий проход между колоннами.

### 4.6 Зоны обзора [П]

| Позиция | Что видно хорошо | Что видно плохо |
| :--- | :--- | :--- |
| За столом, лицом в класс | Периферийные экраны под углом, спины | Экраны острова — с ребра; руки за телами |
| Кольцевой проход | Экраны и спины вблизи | Руки за столом, противоположная сторона острова |
| Левый проход (у двери) | Левая стена и остров сбоку | Правая стена, тень |
| Правый проход (у окон) | Правая стена и остров сбоку | Левая стена, блики на экранах |
| Центральный проход острова | — | Узкий, не предназначен для ходьбы |

- **Левая сторона** — тень: без окон, руки хуже различимы. Помогает CCTV.
- **Правая сторона** — свет: ученики на просвет, на экранах блики. Помогает CCTV, но мешает читать вживую.
- **Остров** — слепая зона для рук; экраны видны только из боковых проходов.

### 4.7 Свет [П]

- Основной источник — направленный свет из 4 двойных окон справа, угол ~25° вниз.
- Запечённые световые карты, без realtime GI; 1–2 потолочных заполняющих источника.
- Экраны моноблоков — слабая эмиссия.
- На экранах правой стены — лёгкий шейдер блика/отражения окна.
- **Опционально:** жалюзи на правой стене (`[П]`). Закрыть → меньше бликов, но темнее в классе; ещё один тактический выбор. В MVP не входит.

### 4.8 Рабочее место ученика [Т]

| Объект | Назначение |
| :--- | :--- |
| Моноблок | ПК и экран в одном корпусе. Показывает редактор кода или браузер; это же изображение идёт в CCTV. |
| Клавиатура | Анимация печати, звук, телл «печатает / не печатает». |
| Мышь + коврик | Клики и движение; телл «активен / простой». Справа от клавиатуры (у левши — слева). |
| Стул | Посадка, наклон, отъезд. |
| Телефон (0–2) | Карман, под партой, рюкзак. Объект для обыска. |
| Рюкзак | Место хранения второго телефона; под столом, так как системного блока нет. |

### 4.9 Рабочее место преподавателя [Т]

| Объект | Действие |
| :--- | :--- |
| Кресло | Сесть / встать. Переход 1,2 с. |
| Моноблок | Один экран с окнами: CCTV, Excel, GPT. Переключение окон — 0,2–0,4 с. [Т] |
| Коробка телефонов | Сбор, подсчёт, осмотр. На правом краю стола. [Т] |
| Журнал | Список 15 учеников, варианты, известные устройства. |
| Доска | За спиной, нижняя стена. Брифинг, схема, проектор. |

**Примечание.** На макете у преподавателя один моноблок; отдельные три монитора не подтверждены. Все программы — окна на одном экране. Второй монитор возможен как стретч, но не в MVP.

## 5. Управление и режимы

### 5.1 Режим «За столом» [Т]

- Камера сидячая, высота глаз 1,2 м, FOV 65°, можно вращать мышью на 360°.
- Движение (WASD) заблокировано.
- Доступен ПК: CCTV, Excel, GPT.
- Видно весь класс, но мелкие детали (руки под партой, текст на экране) неразличимы.

### 5.2 Режим «В классе» [Т]

- Встать: `E` у кресла, 1,2 с.
- Движение: WASD, скорость **1,6 м/с**, без бега.
- Камера: высота 1,65 м, FOV 75°.
- Взаимодействие: `E` — луч 3 м, конус 35°.
- Доступно: подойти к ученику, посмотреть экран, поговорить, обыскать парту.
- ПК недоступен: чтобы смотреть CCTV, надо вернуться и сесть.

### 5.3 Ключевые действия

| Клавиша | Действие |
| :--- | :--- |
| `WASD` | Движение (в режиме «В классе») |
| Мышь | Обзор |
| `E` | Контекст: сесть/встать, открыть экран, поговорить, обыскать |
| `Tab` | Журнал (чтение; доп. вариант — через Excel) |
| `Esc` | Пауза, закрыть полноэкранный фид, выйти из диалога |
| `F` | Скриншот в полноэкранном CCTV |
| `C` | Наклониться (заглянуть под парту) |

### 5.4 Тайминги переходов [П]

| Действие | Время |
| :--- | :--- |
| Сесть / встать | 1,2 с |
| Открыть CCTV-сетку | 0,8 с (первый раз), далее 0,2 с |
| Открыть фид на весь экран | 0,3 с |
| Вернуться к сетке | 0,2 с |
| Открыть Excel | 0,4 с |
| Открыть GPT | 1,2 с |
| Скриншот | 0,8 с |
| Обыск парты | 8,0 с |
| Замечание | 1,5 с |
| Конфискация | 3,0 с |

## 6. Таймлайн сессии

```
ПОДГОТОВКА 90 с → ПАРА 10 мин → [проверка сдач 2,5 с] → ИТОГИ
```

**Длительность пары фиксирована — 10 минут на всех уровнях.** Сложность растёт за счёт числа читеров, методов и качества теллов, а не за счёт времени.

### 6.1 Подготовка (90 с, можно пропустить) [Т]

1. Брифинг: цель, состав, длительность.
2. Расстановка вариантов в Excel: 15 строк, пул 1–15.
3. Проверка валидации: пусто — жёлтый, дубликат — красный, всё уникально — зелёный.
4. Опционально: попросить сдать телефоны заранее.
5. «Начать пару».

Если подготовка закончилась с пустыми ячейками — автозаполнение случайными номерами **с дубликатами**, доверие класса −10. [П]

### 6.2 Пара [Т]

- Таймер идёт только в состоянии «Пара».
- Пауза (`Esc`) останавливает таймер, ИИ, анимации и звук.
- Ученики работают, задают вопросы, пытаются списать.
- Преподаватель свободно перемещается и пользуется ПК.

### 6.3 Звонок

- За 60 с и 30 с — предупреждение (звук + HUD).
- В 0:00 звонок. Все незавершённые сдачи отменяются.
- **Исключение:** если сдача началась до звонка, ей даётся 2,5 с на завершение. Это проверяется до объявления итога. [П]

### 6.4 Итоги

- Победа: `successful_cheats == 0`.
- Поражение: `successful_cheats >= 1` (объявляется сразу в момент сдачи, см. §16).
- Экран итогов: статистика, разбор, кнопки «Заново», «В меню», «Следующий уровень».

## 7. Действия преподавателя

## 8. Модель ученика

### 8.1 Параметры

| Параметр | Диапазон | Смысл |
| :--- | :--- | :--- |
| `diligence` | 1–5 | Желание работать честно |
| `skill` | 1–5 | Скорость честной работы |
| `risk` | 1–5 | Склонность рисковать |
| `attention` | 1–5 | Как быстро замечает преподавателя |
| `sociability` | 1–5 | Готовность помогать/подсказывать |
| `methods` | список | Доступные способы списывания |
| `phones_known` | 0–2 | Известные устройства (видно в журнале) |
| `phones_hidden` | 0–1 | Скрытое устройство (не видно) |
| `quirk` | строка | Особенность поведения |

### 8.2 Прогресс работы

- `lab_progress` 0–`lab_target` — сколько работы сделано.
- `lab_target = 100 × (1 + extra_count)` — сколько нужно для сдачи; `extra_count` 0–10.
- `copied` 0–`lab_target` — сколько из этого скопировано.
- `extra_variants` — список номеров доп. вариантов (до 10).
- Честная работа: `lab_progress += honest_rate * dt`, `copied` не меняется.
- Списывание: `lab_progress += cheat_rate * dt`, `copied += cheat_rate * dt`.
- Если `lab_progress >= lab_target` → `SUBMIT`.
- Сдача списанной работы: `copied > 0` на момент завершения.
- **Доп. вариант:** `lab_target += 100`, `lab_progress -= copied`, `copied = 0`. Честная часть сохраняется, скопированная удаляется.

**Честная скорость [П]:**

| Навык | %/с | Время до 100% |
| :--- | :--- | :--- |
| 5 | 0,25 | ~400 с (6,7 мин) |
| 3 | 0,18 | ~555 с (9,2 мин) |
| 1 | 0,10 | ~1000 с (не успевает) |

С одним доп. вариантом цель 200%, время честной работы ×2; каждый следующий добавляет ещё +100%. Технический предел — +10 вариантов (цель до 1100%), но это уже гарантированный `F`, а не баланс. Практично 1–2. [П]

### 8.3 Состояния (FSM)

```
        ┌──────────┐  score > threshold   ┌──────────┐
        │   WORK   │ ───────────────────▶ │   PEEK   │
        └────┬─────┘                      └────┬─────┘
             │                                  │ выбор метода
             │ вопрос                           ▼
        ┌────▼─────┐                    ┌──────────────┐
        │ QUESTION │                    │  CHEAT_*     │
        └──────────┘                    └──┬───┬───┬───┘
                                           │   │   │
                              замечен ─────┘   │   └───── lab ≥ target
                                 ▼             │            ▼
                            ┌────────┐         │      ┌──────────┐
                            │  HIDE  │         │      │  SUBMIT  │
                            └───┬────┘         │      └────┬─────┘
                                │ 1–3 с        │           │
                                ▼              │           ▼
                              WORK             │        DONE / LOSS
```

| Состояние | Длительность | Что видно | Выход |
| :--- | :--- | :--- | :--- |
| `WORK` | до `lab_target` | Печатает, взгляд в монитор | `PEEK`, `QUESTION`, `SUBMIT` |
| `PEEK` | 1–3 с | Пауза, оглядывается | `CHEAT_*` или `WORK` |
| `CHEAT_GPT` | 15–20 с цикл | Браузер с чатом | `HIDE`, `WORK` |
| `CHEAT_SEARCH` | 6–10 с цикл | Поисковая выдача | `HIDE`, `WORK` |
| `CHEAT_CLASSROOM` | 12–20 с | Classroom, готовое решение | `HIDE`, `WORK` |
| `CHEAT_PHONE` | непрерывно | Монитор без изменений, голова вниз | `HIDE`, `WORK` |
| `HIDE` | 1–3 с | Редактор кода, «печатает» | `WORK` |
| `QUESTION` | до ответа | Поднятая рука, звук | `WORK` |
| `SUBMIT` | 2,5 с | «Сдать работу», рука тянется к мыши | `DONE` / отмена |
| `DONE` | — | Сидит, ждёт | — |

### 8.4 Восприятие преподавателя [П]

Ученик «видит» преподавателя, если:

- расстояние ≤ 12 м;
- угол между направлением взгляда преподавателя и учеником ≤ 55°;
- есть прямая видимость (нет препятствия).

Реакция:

```
reaction = base_reaction(0.4–1.8 с) * (1.2 − attention / 10)
```

- Если ученик в `CHEAT_*` и видит преподавателя → после `reaction` уходит в `HIDE`.
- Если преподаватель ближе 1,5 м и смотрит прямо → шанс спрятаться 0,3–0,5 (пойман с поличным).
- Если преподаватель сидит за ПК → ученики считают его «занятым» с вероятностью 0,8 → `opportunity` растёт.
- Телефон: если преподаватель ближе 2,5 м или смотрит → ученик прячет телефон за 0,4–1,2 с.

### 8.5 Принятие решения [П]

Каждые 0,5 с в состоянии `WORK`:

```
need        = (1 − lab_progress / 100) * urgency(time_left)
opportunity = 0.5 * teacher_at_pc + 0.5 * teacher_far
detection   = 0.6 * gaze_on_me + 0.4 * proximity
score       = 1.2*need + 1.0*(risk/5) + 0.8*opportunity
              − 1.5*detection + personality_bias + noise(seed)
```

- `urgency` растёт к финалу: ×1,0 → ×1,6 за последние 2 минуты.
- `noise` — детерминированный шум от seed сессии.
- Если `score > threshold(archetype)` → `PEEK`, затем выбор метода с максимальным score.
- После санкции — кулдаун 20–40 с, в течение которого `risk` снижен.

## 10. CCTV

### 10.1 Что показывает [Т]

CCTV — это **трансляция экранов мониторов**, а не камеры наблюдения за людьми. Видно только то, что на мониторе ученика. Руки, телефоны и лица не видны. Это ключевое ограничение: телефонный метод CCTV не ловит.

### 10.2 Параметры [П]

| Параметр | Сетка | Полный экран |
| :--- | :--- | :--- |
| Раскладка | 3 строки × 5 столбцов | 1 фид |
| Разрешение | 320 × 180 на фид | 1280 × 720 |
| Частота обновления | 6 FPS | 20 FPS |
| Задержка | 0,2 с | 0,2 с |
| Оверлей | Номер места, имя, вариант, статус | Номер, имя, вариант, таймкод, кнопка «Скриншот» |

- Физическая рассадка — U-образная (см. §4), поэтому сетка **не зеркалит класс**. Она заполняется по номерам мест: 1–5 / 6–10 / 11–15.
- В углу сетки — **мини-карта класса**: 15 точек по фактическим местам; выбранное место подсвечивается. Это компенсирует отсутствие пространственного соответствия.
- На каждом фиде — номер места и буква зоны (T/L/R/C), чтобы быстро находить ученика.
- Клик по фиду — открыть на весь экран. `Esc` или повторный клик — назад.
- Если монитор выключен или заблокирован — серый фид с надписью «нет сигнала».

### 10.3 Статусы фида [П]

| Индикатор | Значение |
| :--- | :--- |
| Печатает | Активность клавиатуры за последние 2 с |
| Кликает | Активность мыши за последние 2 с |
| Простой | Нет ввода > 8 с |
| Смена окна | Рамка фида коротко подсвечивается при переключении вкладки |
| Поднятая рука | Иконка `✋` поверх фида |

Подсветка смены окна нужна, чтобы 15 мелких фидов были читаемы при сканировании. Без неё игрок физически не успевает.

### 10.4 Чего CCTV не даёт

- Не видно, что ученик делает руками.
- Не видно, смотрит ли он на телефон.
- Не видно, спрятал ли он второй телефон.
- Нельзя понять, «честный» ли код, без чтения.

Поэтому CCTV — инструмент для PC-методов, а прогулка — для телефона.

## 11. Улики и доказательства

### 11.1 Два уровня

| Уровень | Как получен | Что позволяет |
| :--- | :--- | :--- |
| **Подозрение** | Любой телл: простой монитора, браузер, голова вниз, свечение | Замечание |
| **Доказательство** | Скриншот экрана с таймкодом **или** прямое наблюдение ≥ 1,0 с с ≤ 3 м | Конфискация, «вернуться к работе», овайп |

### 11.2 Скриншот

- Доступен только в полноэкранном фиде.
- Сохраняет: `student_id`, `method` (если распознан), таймкод, миниатюру.
- Собирается в «дело» и показывается в итогах.
- Скриншот чистого экрана не является доказательством и не даёт санкций.

### 11.3 Прямое наблюдение

- Условие: преподаватель ≤ 3 м, смотрит на экран/руки, непрерывно 1,0 с.
- Если ученик успел спрятаться за 0,4–1,2 с — доказательство не получено, остаётся подозрение.
- Если преподаватель подошёл вплотную (≤ 1,5 м) и смотрит — шанс улики 0,7–0,9.

### 11.4 Ложные улики

Их нет. Скриншот всегда правдив. Ошибка игрока — применить санкцию без улики или не к тому ученику.

## 12. Санкции

| Санкция | Условие | Эффект на прогресс | Эффект на поведение | Время | Ложная санкция |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Замечание** | Подозрение | `copied −= 25%` от текущего | `risk −30%` на 30 с, пауза 5 с | 1,5 с | Доверие −5, раздражение +10 |
| **Вернуться к работе** | Доказательство | `lab_progress −= copied`, `copied = 0` | `risk −50%` на 60 с, пауза 10 с | 2 с | Доверие −10 |
| **Конфискация** | Доказательство устройства | То же + устройство изъято | Телефонный метод недоступен | 3 с | Доверие −10, раздражение +15 |
| **Обыск парты** | ≤ 1,5 м | — | Шанс найти скрытое устройство 0,4–0,8 | 8 с | Доверие −3, раздражение +10 |
| **Доп. вариант** | Доказательство, до +10 на ученика | `lab_target += 100`, `lab_progress −= copied`, `copied = 0` | Ещё один вариант, раздражение +20, `risk +25%` на 90 с | 4 с | Доверие −15 |
| **Овайп** | Доказательство + повторное нарушение | `lab_progress = 0`, `copied = 0` | `risk −60%` у всех на 30 с | 4 с | Доверие −20 |

**Правила:**

- Любая санкция прерывает текущую попытку и переводит ученика в `WORK`.
- Кулдаун замечания на одного ученика — 20 с.
- Санкция не отменяет уже завершённую сдачу.
- «Вернуться к работе» и «Доп. вариант» полностью очищают `copied`. Без этого списанная работа останется списанной.
- **Доп. вариант** — до +10 вариантов на ученика; каждый добавляет +100% к цели. Назначается только с доказательством, превентивно «всем» — нельзя. Практично 1–2: дальше цель недостижима.
- Доверие класса влияет на скорость реакции и смелость, но не на победу/поражение.

- **Строки** — 15 учеников.
- **Столбцы** — занятия/даты; в игре активен один столбец «сегодня», прошлые — серым как история. [П]
- **Ячейка** — двухстрочная: сверху вариант(ы) `5` или `5+6+7`, снизу статус `зач`, `отч`, `не сдал` или пусто.
- **Пустая клетка** — ничего не сдал; вариант всё равно виден над клеткой (в шапке столбца и верхней строке ячейки).
- **Шапка** — группа, дата, номер пары, «подгруппа».
- В подготовке ячейки сегодняшнего столбца заполняются вариантами 1–15.
- Пул номеров 1–15; drag-and-drop или выбор ячейки.
- Валидация: пусто — жёлтый, дубликат — красный, всё уникально — зелёная рамка «Готово».
- «Автозаполнить» — валидная случайная раскладка, 20 с подготовки.
- «Начать пару» — только при заполненных ячейках. [П]

**Для MVP:** один активный столбец. История прошлых занятий — стретч, но она даёт преподавателю повторных нарушителей, поэтому заложена в модель.

### 13.2 Статусы и цвета [Т]

| Ячейка | Цвет | Значение |
| :--- | :--- | :--- |
| `зач` | зелёный | Всё чётко: работа сдана и отчёт загружен |
| `отч` | жёлто-зелёный | Работа сдана преподавателю, отчёт не загружен |
| `7` | жёлтый | Работает над вариантом 7 |
| `7+12+13` | оранжевый | Свой 7 + доп. 12 и 13 (санкция) |
| `не сдал` | красный | Пара закончилась без сдачи |
| пусто | серый | Ничего не сдал; вариант виден над клеткой |

**Подтверждено:** `зач` — всё чётко; `отч` — работа сдана, отчёт не загружен; пустая клетка — ничего не сдал. `чек` — платная отработка, **в игре не используется**.

**В игре [П]:** `отч` ставится, если ученик сдал код, но не загрузил отчёт (шанс зависит от архетипа). На победу/поражение это не влияет; преподаватель может напомнить (2 с), чтобы перевести статус в `зач`.

### 13.3 Доп. вариант [Т]

- Назначается **только пойманному** ученику и только с доказательством.
- Стоимость: 4 с у ПК; до **+10** вариантов на одного ученика.
- Эффект за каждый: `lab_target += 100`, `lab_progress -= copied`, `copied = 0`.
- В ячейке журнала появляется `7+12` (или `7+12+13`); в карточке — «Вариант 7 + доп. 12, 13».
- Ученик обязан сдать все назначенные; если не успел к звонку — `F` (не поражение).
- Условия победы не меняются: сдал списанное — поражение.
- **Почему это не эксплойт:** назначать можно только по доказанному нарушению, действие стоит времени, злит ученика (`risk +25%`) и повышает шанс, что он спишет снова. +10 — технический предел, а не балансная цель.

**Трактовка лимита [П]:** «до +10» считается **на одного ученика**. Если имелось в виду на группу или на пару — поправим конфиг.

### 13.4 Дубликаты [Т + П]

| Ситуация | Эффект |
| :--- | :--- |
| Уникальный вариант | Базовая скорость |
| Дубликат у соседей (одна колонка/ряд) | ×1,5 к скорости списывания |
| Дубликат у дальних учеников | ×1,2 |
| Classroom для дубликата | Полное решение доступно |

### 13.5 Во время пары

- Базовые назначения читаются только по `Tab`; исправить дубликат нельзя.
- Исключение — «Доп. вариант»: единственное изменение журнала во время пары.
- Это делает подготовку значимой: ошибка в Excel усиливает читеров на всю пару.

### 13.6 Слитые варианты [П]

- В пуле 3 варианта помечены как «слитые» (есть в Classroom).
- Преподаватель видит пометку в Excel и может раздать их тем, кто меньше склонен к Classroom.
- Если всем честным достались слитые — риск выше.
- Для MVP можно отключить, оставив только дубликаты.

## 14. Вопросы учеников и ответы

### 14.1 Когда возникает вопрос [Т + П]

- Ученик в `WORK` дошёл до контрольной точки (25 / 50 / 75%) или застрял 40 с.
- Вероятность зависит от `diligence`, `skill` и сложности задания.
- Поднятая рука: анимация, иконка `✋`, звук «мм», запись в HUD.
- Одновременно не больше двух поднятых рук; остальные ждут в очереди.

### 14.2 Два пути ответа [Т]

**A. Через GPT (за столом):**

1. Сесть за ПК, открыть GPT — 1,2 с.
2. Открыть монитор ученика — 0,5 с.
3. Сделать скриншот — 0,8 с.
4. Отправить в GPT — 5 ± 1 с.
5. Прочитать, отправить ответ — 1 с.
6. **Итого:** 9–12 с, в течение которых преподаватель не видит класс.

**B. Вручную (в классе):**

1. Подойти к ученику — 0,5 с на диалог.
2. Прочитать вопрос и код ученика.
3. Выбрать один из **5 вариантов** ответа.
4. **Итого:** 8–20 с, но преподаватель рядом и видит руки.

### 14.3 Качество ответа

| Путь | Верный | Частичный | Неверный |
| :--- | :--- | :--- | :--- |
| GPT | 80–95% | — | 5–20% |
| Вручную | 1 из 5 | 2 из 5 | 2 из 5 |

- Верный: `lab_progress +5%`, раздражение −15, `risk −20%` на 60 с.
- Частичный: `lab_progress +2%`, раздражение −5.
- Неверный: пауза 10 с, раздражение +20, доверие −3, ученик может спросить снова.
- Если вопрос игнорируется > 45 с: раздражение +30, `risk +20%` на 60 с, ученик может перейти к списыванию.

### 14.4 Почему это работает

- GPT экономит ходьбу, но отрывает от наблюдения.
- Ручной ответ держит рядом, но требует времени и знаний.
- Ошибиться можно в обоих случаях — это честный риск.

## 15. Коробка телефонов

### 15.1 Устройства [Т]

- У каждого ученика 0–2 известных устройства (видно в журнале).
- У части учеников есть **скрытое** второе устройство (в журнале не отображается).
- Телефон может быть: в кармане, под партой, в рюкзаке.

### 15.2 Сбор [Т]

- Действие «Сдать телефоны» доступно у стола.
- Все ученики реагируют за 1–4 с.
- Варианты поведения:

| Поведение | Вероятность | Результат |
| :--- | :--- | :--- |
| Сдаёт все известные | зависит от доверия | Слот `n/n` |
| Сдаёт один из двух | если `phones_known = 2` | Слот `1/2` |
| Сдаёт муляж/старый телефон | у части архетипов | Слот `1/1`, но устройство не рабочее |
| Отказывается, «нет телефона» | при низком доверии | Слот `0/1` |
| Прячет второй, неизвестный | у 2–3 учеников | Слот `1/1`, скрытое остаётся |

### 15.3 Подсчёт и проверка [Т]

- «Пересчитать» — 5 с, показывает: сдано N, ожидалось M, расхождения по слотам.
- Слот с расхождением подсвечивается.
- Осмотр коробки — 5 с, позволяет найти муляжи (не включается / старая модель).
- Обыск парты/рюкзака — 8 с, шанс найти скрытое устройство.

### 15.4 Правила

- Сбор можно проводить в подготовке и во время пары, но не чаще одного раза в 3 минуты (иначе доверие −5).
- Во время сбора работа приостанавливается на 10–30 с — это цена.
- Сдавший телефон ученик не может использовать телефонный метод.
- Скрытый второй телефон сохраняет возможность.
- В конце пары телефоны возвращаются (флейвор, на исход не влияет).

### 15.5 Почему нельзя просто собрать все телефоны и победить

- Сбор стоит 30–60 с и снижает темп.
- Часть учеников не сдаёт или сдаёт муляж.
- Главные методы — PC: GPT, Google, Classroom. Они работают без телефона.

## 16. Победа, поражение, итоги

### 16.1 Условия [Т]

| Событие | Условие | Результат |
| :--- | :--- | :--- |
| **Победа** | К звонку `successful_cheats == 0` | Уровень пройден |
| **Поражение** | Любая завершённая сдача с `copied > 0` | Немедленное поражение |

Других условий нет. Таймер истёк, все не сдали — победа, если никто не списал. [Т]

### 16.2 Момент поражения [П]

1. Ученик завершает `SUBMIT` (2,5 с).
2. Игра замедляется на 1,5 с, камера плавно показывает виновника и его экран.
3. Плашка: «Списано. Работа сдана».
4. Экран итогов с разбором.

Это немедленное поражение, а не «дожить до звонка»: иначе вторая половина пары теряет смысл.

### 16.3 Окно сдачи

- `SUBMIT` длится 2,5 с.
- Если преподаватель применяет санкцию с доказательством в это окно — сдача отменяется.
- Отмена сдачи без очистки `copied` бесполезна: ученик сдаст снова.
- Если сдача началась до звонка — она разрешается (2,5 с), даже если звонок уже прозвенел.

### 16.4 Экран итогов

**Победа:**

- «Никто не списал».
- Честных сдач: N/15.
- Остановлено попыток: N.
- Вопросов отвечено: N, ошибок: N.
- Телефонов собрано: N.
- Ложных санкций: N.
- Время.

**Поражение:**

- Кто, каким методом, в какое время.
- Где был преподаватель в этот момент.
- Какие улики были упущены (если были).
- «Что можно было сделать»: 2–3 подсказки.
- Список всех попыток за пару.

## 17. Баланс и сложность

### 17.1 Уровни [П]

| Уровень | Длительность | Потенциальных читеров | Методы | Особенности |
| :--- | :--- | :--- | :--- | :--- |
| 1. Первая пара | 10 мин | 3 | Телефон, Google | Обучение, явные теллы |
| 2. Активные | 10 мин | 5 | + GPT | Быстрее реакция |
| 3. Изощрённые | 10 мин | 7 | + Classroom | Дубликаты, слитые варианты |
| 4. Контроль | 10 мин | 9 | все | Вторые телефоны, наглые |
| 5. Хардкор | 10 мин | 11–12 | все | Кооперация, минимум теллов |

**Длительность пары — 10 минут на всех уровнях.** Сложность растёт только за счёт числа читеров, набора методов и читаемости теллов.

Победа на всех уровнях — ноль списаний. [Т]

### 17.2 Целевые метрики [П]

- Win rate на плейтесте: 30–70% (для уровня 1 — 60–80%).
- Среднее время до первой попытки: 60–120 с.
- Среднее число остановленных попыток за пару: 4–8.
- Ложные санкции: не более 2 за пару у среднего игрока.

### 17.3 Анти-дегенеративные проверки

| Стратегия игрока | Почему не работает |
| :--- | :--- |
| Сидеть за ПК всю пару | Телефоны не видны, вопросы копятся, доверие падает |
| Ходить всю пару | PC-методы не видны; Classroom успевает за 15 с |
| Смотреть в один фид | Остальные 14 свободны |
| Спамить замечаниями | 1,5 с × 15 = 22 с, кулдаун 20 с, ложные санкции бьют доверие |
| Собрать все телефоны | 30–60 с, часть не сдаёт, PC-методы остаются |
| Обыскать всех | 15 × 8 с = 2 мин, треть пары |
| Выгнать всех | Не реализуем в MVP; при добавлении — штраф за срыв пары [О] |

### 17.4 Окно реакции

- Между «ученик начал» и «ученик сдал» должно быть **не меньше 12 с** для любого метода.
- Для Classroom — минимум 12 с (вставка + проверка).
- Для телефона — 60–120 с, но он невидим в CCTV.
- Это гарантирует, что игрок физически успевает вмешаться, если смотрит.

## 21. Техническая архитектура

### 21.1 Стек [П]

Рекомендация после перехода на 3D остаётся прежней:

| Компонент | Выбор |
| :--- | :--- |
| Движок | **Godot 4.3** (пин версии) |
| Язык | GDScript со статической типизацией |
| Рендер | Forward+ (fallback: `gl_compatibility`) |
| 3D | Low-poly класс, baked lightmaps, 1 real-time light |
| Экраны учеников | `SubViewport` 320×180, 2D-UI, общий источник для 3D-монитора и CCTV |
| UI | `Control` + `Theme` |
| Данные | `Resource`/`.tres` + JSON |
| Тесты | GUT + headless-прогон |
| CI | GitHub Actions: импорт, тесты, экспорт Windows |
| VCS | Git + Git LFS (`png`, `wav`, `glb`, `ttf`) |

**Почему не Unity:** каркас уже в Godot, headless-тесты проще, нет лицензионных и весовых проблем для учебных ПК. Если ТЗ требует Unity — см. §27.

### 21.2 Как рендерить 15 экранов

**Не делать 15 3D-камер и 15 RenderTexture комнаты.** Это дорого и не нужно.

Правильно:

1. У каждого ученика — `SubViewport` с 2D-UI (редактор кода / браузер).
2. Текстура этого вьюпорта используется **и** на 3D-мониторе, **и** в CCTV-сетке. Один источник, без двойного рендера.
3. Обновление: 6 FPS в сетке, 20 FPS в полноэкранном режиме, 10 FPS для мониторов, видимых в 3D.
4. Когда фид не виден — `UPDATE_ONCE` или пауза.
5. Бюджет: 15 × 320×180 × 6 FPS ≈ 5,2 Мпикс/с — копейки.

### 21.3 Бюджет кадра

| Метрика | Бюджет |
| :--- | :--- |
| FPS | 60 при 1080p, минимум 30 |
| Симуляция | < 2 мс |
| UI | < 4 мс |
| Рендер | < 8 мс |
| Draw calls | < 150 |
| Треугольники | < 100 тыс. |
| ОЗУ / VRAM | < 1,5 ГБ / < 1 ГБ |

Ученики: low-poly 2–4 тыс. треугольников, общий риг, 5–6 анимаций (idle, type, look, lean, phone, raise hand), без теней, blob-тени.

| `Phones` | Коробка, устройства, обыск |
| `Questions` | Вопросы, 5 вариантов, GPT |
| `CCTV` | Сетка, зум, скриншот |
| `Save` | JSON, миграции, backup |
| `Audio` | Пул источников, 3D |

**Правило:** домен не знает о 3D. Симуляция — чистые классы, которые можно прогнать без сцены.

### 21.5 Headless-тесты

- Проверяет: нет исключений, распределение исходов, время до первой попытки, эффективность санкций.
- 1000 сессий без сцены и рендера.

### 21.6 Ассеты

## 22. Сценарии

Формат: **Предусловие → Шаги → Ожидание → Защита от ошибки.**

### С-01. Идеальная победа

**Предусловие:** уровень 2, 5 читеров.
**Шаги:** раздать варианты → сесть → сканировать сетку → замечать браузер → зум → скриншот → «вернуться к работе» → иногда вставать и ловить телефоны → отвечать на вопросы.
**Ожидание:** 0 сдач с `copied > 0`, к звонку победа.
**Защита:** если игрок только сидит — телефонные читеры дожимают до 100%.

### С-02. GPT пойман через CCTV

**Предусловие:** ученик 5 в `CHEAT_GPT`, преподаватель за столом.
**Шаги:** сетка → заметить браузер → открыть фид → скриншот → «вернуться к работе».
**Ожидание:** `copied = 0`, ученик в `WORK`, улика в деле.
**Защита:** скриншот до того, как ученик спрятался (реакция 0,4–1,2 с).

### С-03. GPT не пойман

**Предусловие:** преподаватель смотрит другой фид.
**Шаги:** ученик завершает 2–3 цикла → `lab_progress = 100` → `SUBMIT`.
**Ожидание:** поражение, разбор: «ученик 5, GPT, 04:12».
**Защита:** HUD-подсветка смены окна и звук помогают заметить.

### С-04. Телефон пойман в классе

**Предусловие:** ученик 7 с телефоном, преподаватель встал.
**Шаги:** подойти сбоку ≤ 2,5 м → увидеть свечение/руку → 1,0 с → доказательство → конфискация.
**Ожидание:** телефон изъят, `copied = 0`, ученик продолжает.
**Защита:** если подходить в лоб — ученик прячет за 0,4–1,2 с; нужен угол.

### С-05. Телефон не пойман

**Предусловие:** преподаватель сидит за ПК.
**Шаги:** ученик 7 списывает 100 с → сдаёт.
**Ожидание:** поражение, разбор: «телефон, CCTV не показывает руки».
**Защита:** подсказка в итогах: «вставайте из-за стола».

### С-06. Classroom пойман в окне сдачи

**Предусловие:** ученик 6 вставил решение, `lab_progress = 95`, идёт `SUBMIT`.
**Шаги:** заметить мгновенный код → открыть фид → скриншот → «вернуться к работе» за 2,5 с.
**Ожидание:** сдача отменена, `lab_progress −= copied`.
**Защита:** если применить только замечание — останется 75% копии, и ученик сдаст снова.

### С-07. Classroom успел

**Предусловие:** преподаватель в другом конце класса.
**Шаги:** ученик завершает `SUBMIT`.
**Ожидание:** поражение; в разборе видно, что окно было 12 с.
**Защита:** подсветка «код появился целиком» и звук.

### С-08. Вопрос через GPT

**Предусловие:** ученик 5 поднял руку.
**Шаги:** сесть → GPT → монитор ученика → скриншот → 5 с → отправить.
**Ожидание:** верный ответ, `lab_progress +5%`, `risk −20%`.
**Защита:** пока преподаватель в GPT, класс без присмотра — кто-то может начать.

### С-09. Неверный ручной ответ

**Предусловие:** вопрос ученика 4.
**Шаги:** подойти → прочитать код → выбрать неверный вариант.
**Ожидание:** пауза 10 с, раздражение +20, доверие −3; ученик может спросить снова.
**Защита:** GPT снижает риск ошибки, но стоит времени.

### С-10. Вопрос проигнорирован

**Предусловие:** рука поднята 45 с.
**Шаги:** игрок не реагирует.
**Ожидание:** раздражение +30, `risk +20%` на 60 с; повышенная вероятность списывания.
**Защита:** повторный звук и мигающая иконка.

### С-11. Сбор телефонов, все сдали

**Предусловие:** подготовка.
**Шаги:** «Сдать телефоны» → подождать 10–30 с → пересчитать.
**Ожидание:** сдано = ожидаемому, телефонный метод отключён у всех.
**Защита:** PC-методы остаются, расслабляться нельзя.

### С-12. Второй телефон

**Предусловие:** ученица 9, `phones_known = 2`, сдала один.
**Шаги:** слот `1/2` → подойти → обыск → найти второй (шанс 0,6).
**Ожидание:** второй изъят; если не нашли — продолжает списывать.
**Защита:** слот с расхождением подсвечен, но не гарантирует находку.

### С-13. Муляж

**Предусловие:** ученица 15 сдаёт старый телефон.
**Шаги:** слот `1/1` → осмотреть коробку.
**Ожидание:** устройство не включается → признано муляжом → обыск → найти рабочий.
**Защита:** без осмотра коробки муляж считается сданным.

### С-14. Дубликаты усиливают списывание

**Предусловие:** в Excel у соседей один вариант.
**Шаги:** начать пару.
**Ожидание:** скорость Classroom/GPT у пары ×1,5; в итогах отмечено.
**Защита:** валидация предупреждает красным до старта.

### С-15. Старт с пустыми вариантами

**Предусловие:** игрок пропустил подготовку.
**Шаги:** «Начать».
**Ожидание:** автозаполнение с дубликатами, доверие −10, предупреждение.
**Защита:** кнопка «Начать» неактивна, пока не заполнено (для MVP). [П]

### С-16. Ложные санкции

**Предусловие:** игрок трижды наказал честных.
**Шаги:** замечания без теллов.
**Ожидание:** доверие падает, ученики смелее, реакции медленнее; победа всё ещё возможна.
**Защита:** доверие не приводит к поражению — иначе игрок не понимал бы, за что проиграл.

### С-17. Два читера одновременно

**Предусловие:** ученики 5 и 6 начали.
**Шаги:** преподаватель может спасти только одного.
**Ожидание:** второй успевает → поражение.
**Защита:** это честная цена выбора; в разборе видно оба.

### С-18. Сдача на последней секунде

**Предусловие:** `lab_progress = 100` за 0,5 с до звонка.
**Шаги:** звонок.
**Ожидание:** сдача разрешается 2,5 с; если `copied > 0` — поражение.
**Защита:** таймер не «съедает» начатую сдачу.

### С-19. Пауза и Alt+Tab

**Предусловие:** идёт пара.
**Шаги:** `Esc` / свернуть окно.
**Ожидание:** таймер, ИИ, анимации и звук стоят; после возврата всё продолжается.
**Защита:** авто-пауза при потере фокуса.

### С-20. Рестарт после поражения

**Предусловие:** поражение.
**Шаги:** «Заново».
**Ожидание:** новый seed, чистые состояния, те же настройки уровня.
**Защита:** старые улики и статистика не переносятся.

### С-21. Доп. вариант

**Предусловие:** ученик 6 пойман с Classroom, доказательство есть.
**Шаги:** сесть за ПК → Excel → выбрать ученика → «Доп. вариант» → назначить 12.
**Ожидание:** ячейка `6+12`, `lab_target = 200`, `copied = 0`; ученик должен сдать оба варианта.
**Защита:** всего до +10 вариантов; без доказательства кнопка недоступна; если сдаст списанное — поражение.

### С-22. Доп. вариант спровоцировал списывание

**Предусловие:** ученик 6 получил доп. вариант, времени мало.
**Шаги:** ученик возвращается к Classroom, чтобы успеть.
**Ожидание:** повышенный `risk`; если преподаватель не смотрит — сдача и поражение.
**Защита:** это осознанная цена санкции: она выигрывает время, но повышает давление.
